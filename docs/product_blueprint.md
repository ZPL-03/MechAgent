# 产品蓝图

MechAgent 面向工程仿真使用者和工具开发者：工程师描述问题、检查建模假设与结果证据，开发者通过契约接入能力和外部工具。产品交付包含交互工作台、自动化入口、结构化结果和可复核报告。

## 用户任务

| 任务 | 产品行为 | 用户需要核对的内容 |
| --- | --- | --- |
| 定义仿真 | 输入自然语言，识别能力与缺项 | 尺寸、材料、方向、区域、边界条件 |
| 执行分析 | 按能力选择工具，生成网格和求解输入 | 执行契约、网格质量、工具状态 |
| 检查结果 | 展示模型、网格、位移和可用应力 | 场量、单位、变形倍率、实际数据来源 |
| 判断可信度 | 分开显示执行状态与参考验收 | 参考来源、误差、阈值、未验证项 |
| 复现与集成 | 导出报告、摘要和 CLI 命令 | 请求、配置、阶段产物是否齐全 |

Studio、CLI 和 SDK 共用 Python 能力与编排链路。当前 Studio 部署模型是本地单用户 SQLite 队列；多用户项目管理、集中权限和集群队列属于部署扩展。服务器作业记录支持状态查询和结果恢复，完整语义见[Studio 使用指南](studio_ui.md)。

## 工程工作台

界面以模型视口为视觉主体。输入区负责请求、预检和案例选择；检查器负责验收、执行流程、Agent 活动、产物与 JSON；报告保留工程解释和失败诊断。中英文界面与明暗主题属于呈现设置，不改变请求和数值结果。操作见 [Studio 使用指南](studio_ui.md)，视觉约定见 [设计系统](design_system.md)。

## 3D 可视化目标与实现

Three.js 根据后端公开场景绘制模型，画布在初始化、交互、尺寸或视图变化时按需渲染。几何视图表达参数外形、尺寸、边界与载荷；网格视图表达节点和单元；结果视图表达位移、可用应力、变形倍率与图例。XYZ 小视口跟随主相机旋转。

结果视图使用求解文件中的网格和场数据。缺少网格或场量时，结果视图显示不可用状态。场量完整性和跨工具一致性由后端适配与验证负责；参数化几何预览与求解结果视图分开表达。

## 产品边界

内置结构静力的模型族、方向、材料和 CAD 候选限制以[能力说明](capabilities.md)为准；网格与求解实现见[工具说明](solver_mesh.md)。产品不将 LLM 建议作为数值结果，也不将执行成功自动解释为验收通过。

工具注册支持求解器、网格器、CAD 内核和执行器。后处理使用 `PostProcessor`，材料使用内置目录，二者尚无独立工厂注册 API。面向商业或开源工具的扩展均需声明真实接口、失败行为和验证证据，专用格式由适配器内部管理。

## 能力进入产品的条件

能力须具备结构化输入、执行契约、真实工具产物、评价依据、失败诊断、自然语言案例和报告字段。Studio 还需提供对应的模型与结果表达。能力成熟度与阶段依赖由[长周期开发计划书](development_plan.md)统一维护；测试和发布流程见[验证与质量门禁](validation.md)。
