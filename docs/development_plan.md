# MechAgent 生产级演进目标

本文定义 MechAgent 从本机可验证原型到生产级 CAE/FEA 多智能体平台的目标、边界、依赖和发布门禁。生产级表示输入、执行、结果、证据、权限、失败恢复和版本兼容均有明确契约与验证，不表示覆盖所有物理域或所有 CAD/求解器。

## 目标定义

MechAgent 的目标产品是一个可部署、可审计、可扩展的 CAE/FEA 仿真平台：工程意图经过结构化建模、能力门禁、几何与网格处理、求解器执行、结果评价和证据归档，输出可复核的工程结论。LLM 负责自然语言理解、候选方案和解释；数值结果只能来自已注册工具及其验证证据。

生产发布必须同时满足以下条件：

1. 输入契约、单位、坐标、区域、材料、载荷、边界、分析步和求解控制均可序列化、校验和版本化。
2. 每个能力声明支持范围、工具绑定、失败行为、参考来源、验收阈值和不适用条件。
3. 每个作业具有幂等标识、完整状态机、资源约束、取消语义、失败归因、产物索引和可验证证据。
4. 求解器、网格器、CAD 内核、后处理器和执行器通过稳定适配器契约接入；插件不会依赖进程内隐式状态。
5. 公开 API、SDK、CLI、Studio 和报告使用同一数据契约；兼容性、迁移和弃用规则可执行。
6. 发布范围内的每个工程能力同时具备真实运行记录和至少一类独立验收证据。
7. 凭据、原始 prompt、内部 Agent 状态、第三方日志和工程文件按访问边界处理；安全失败不会静默降级。

## 当前基线与缺口

`v0.2.0` 的已验证基线为结构线弹性静力梁、矩形板、参数化开孔薄板和矩形实体，默认工具为 CalculiX、CalculiX INP、Gmsh OCC 和本地执行器。Studio 已具备 SQLite 作业记录、独立 worker、取消、重试、重启查询、幂等提交和运行清单校验。Abaqus 只有独立本机检查，不是平台注册后端。

当前基线不提供以下生产能力：

- 身份认证、组织/项目隔离、角色权限、审计主体和多用户资源配额。
- 面向稳定客户端的版本化 API、数据库迁移、对象存储、备份恢复和灾难演练。
- Abaqus 注册适配器、许可证/队列管理、CalculiX 与 Abaqus 的同输入对比闭环。
- 任意 CAD 拓扑保真、区域语义映射、装配体处理、网格收敛自动控制和网格质量统一模型。
- 非线性、接触、屈曲、模态、动力学、热结构、多物理场、CFD/FSI 和优化的发布能力。
- 可观测性、供应链安全、SBOM、签名发布、漏洞响应和长期兼容策略。

上述缺口属于发布条件，不用界面包装或 LLM 解释替代。

## 总体架构目标

```text
客户端 / SDK / CLI
        ↓ 版本化 API
身份、项目、权限与审计层
        ↓
作业服务 ── 队列 ── 调度器 ── Worker Supervisor
        ↓                         ↓
仿真案例契约                 工具适配器注册表
        ↓              ┌──────────┼──────────┐
能力门禁与评价器       CAD/网格   求解器    后处理
        ↓              └──────────┼──────────┘
证据索引与对象存储 ← 运行产物、日志、报告、场量
```

`mechagent-core` 只负责稳定的数据模型、工具抽象、材料/后处理/验证基础能力；`mechagent` 负责 API、SDK、CLI、编排、队列、权限边界和知识层。任何后端均通过注册名、工厂函数、能力声明和版本化适配器契约接入，不把 Abaqus、CalculiX、某个文件格式或某个中间表示内嵌为通用内核。

## 迭代阶段

### P0：发布基线治理

目标是形成可持续维护的工程基线，而不是扩大物理范围。

- 统一版本、API 路径、配置 schema、能力 ID、错误码、状态枚举和证据 schema。
- 为数据库、运行清单、API 响应和 Pydantic 模型定义版本迁移策略；未知未来版本必须拒绝读取。
- 删除重复文档、过期截图、失效示例和未引用资源；每个专题只保留一个权威入口。
- 固化便携 CI、Windows 真实求解、前端构建、包安装、文档构建、清理和证据校验门禁。
- 生成 SBOM、许可证清单、构建元数据和可复核 SHA-256；发布 tag 与包版本必须一一对应。

完成条件：干净环境可安装、可运行、可验证；文档、OpenAPI、配置、CLI 帮助和代码路由无漂移；没有高严重度未决缺陷。

### P1：稳定仿真案例与契约层

目标是让结构静力成为可长期兼容的参考能力。

- 引入 `SimulationCase`、`GeometryModel`、`Region`、`MaterialModel`、`LoadStep`、`BoundaryCondition`、`SolverControl` 和 `ResultField` 的版本化契约。
- 单位和坐标转换集中管理；禁止通过字段名称或自然语言猜测单位。
- 能力注册项声明输入 schema、工具、支持几何、边界、结果字段、评价器、参考来源和失败代码。
- 解析器输出候选值、来源、置信度和缺项；低置信度或越界输入不得进入求解。
- 报告分开表达执行成功、数值提取成功、参考验收通过和工程适用性。

完成条件：现有 TC-01 至 TC-05、28 个自然语言案例和新增边界案例全部通过契约校验；输入、报告和证据可在兼容版本间迁移。

### P2：可部署的执行与平台层

目标是把单机运行层提升为受控服务。

- API 使用明确版本前缀、OpenAPI schema、错误码、分页、限流和超时；旧客户端拥有弃用周期。
- 增加身份认证、项目隔离、角色权限、作业拥有者、审计事件和工程文件访问控制。
- 作业数据库支持正式迁移、备份、恢复、WAL 处理、归档策略和一致性检查；运行产物进入可配置对象存储。
- Worker Supervisor 管理资源配额、CPU/内存/磁盘限制、容器或受控进程、优雅停止、孤儿回收和重试策略。
- 指标覆盖队列长度、等待时间、执行时间、失败原因、资源使用、产物大小和证据校验；日志结构化并脱敏。
- 重试必须区分可重试基础设施错误、用户输入错误、工具错误和数值未收敛，不自动重跑工程任务。

完成条件：并发、取消、服务重启、Worker 崩溃、数据库恢复、权限越界、重复提交和磁盘不足均有自动化故障测试及清晰结果。

### P3：几何、区域与网格闭环

目标是让 CAD 输入能够保留工程语义，而不是只生成包围盒候选。

- 统一 STEP、IGES、BREP 等格式的单位、坐标系、拓扑实体 ID、面/边/体区域和修复诊断。
- 区域映射必须可见、可编辑、可验证；无法确认的载荷面或约束面进入人工确认状态。
- Gmsh 与其他网格器输出统一节点、单元、区域、质量指标和坐标约定；网格失败保留可诊断中间产物。
- 支持全局和局部尺寸场、质量阈值、网格独立性和收敛报告；不能用单次网格成功替代收敛证据。

完成条件：代表性梁、板、实体、带孔零件和含多个区域的 STEP 案例通过拓扑、区域、网格质量、收敛和结果映射验收。

### P4：多后端结构静力

目标是形成可比较的 CalculiX/Abaqus 结构静力闭环。

- 实现 Abaqus 注册适配器，明确 Standard/Explicit、输入模板、材料、单元、边界、作业状态、ODB 字段和失败映射。
- 许可证检查、命令启动、子进程树、超时、锁文件和 ODB 完整性均由适配器负责。
- 同一 `SimulationCase` 在 CalculiX 和 Abaqus 中生成可比较的模型摘要、位移、应力、反力和能量字段。
- 差异报告记录单元、网格、边界、求解控制和后处理差异；跨后端结果只能在模型和误差阈值明确时比较。

完成条件：至少三类结构静力模型完成同输入双后端对比；每个后端均有独立安装、失败路径、许可证不可用和结果字段测试。

### P5：高级结构与多物理能力

按独立能力发布，不在一个版本中混合多个未验证物理域：

| 能力 | 必要契约 | 发布证据 |
| --- | --- | --- |
| 几何/材料非线性 | 增量步、状态变量、收敛准则、路径输出 | 公开基准、步长/容差收敛、失败诊断 |
| 接触 | 接触对、法向/切向、摩擦、初始间隙 | 接触基准、穿透检查、能量与收敛 |
| 屈曲/模态 | 特征值、预应力、模态归一化、边界 | 解析或公开基准、特征值误差、模态质量 |
| 瞬态/动力学 | 时间步、初始条件、阻尼、时程与能量 | 时间步收敛、能量守恒、公开时程 |
| 热/热结构 | 温度场、材料温度依赖、场映射、单位 | 守恒、场映射误差、网格/时间收敛 |
| 优化/设计探索 | 变量、约束、目标、采样、独立校核 | 基准优化、代理误差、复算和停止原因 |

每项能力达到“研究、可执行、可验证、发布”四级门槛后才进入公开能力目录。

### P6：前端与工程协作

- Studio 提供请求、预检、作业、模型、网格、场量、报告、证据和审计的可追踪链路。
- 3D 视口显示真实节点/单元/场量来源、单位、坐标和变形倍率；示意数据必须明确标注。
- 支持中英文、明暗主题、键盘操作、可见焦点、屏幕阅读器语义、窄屏布局和 reduced-motion。
- 运行中的取消、断线、权限拒绝、队列满、结果缺失、证据失效和未验证状态必须在界面中可理解地呈现。
- 组件、颜色、间距、字体、图标和状态反馈全部来自设计令牌；设计系统与代码组件保持可追踪映射。

完成条件：WCAG 2.2 AA 核心检查通过；真实作业、失败作业、断线恢复、权限边界和大结果集均有浏览器验收。

### P7：安全、供应链与运维

- 密钥只来自受控运行时，禁止进入数据库、manifest、日志、报告、前端响应和构建产物。
- 依赖锁定、SBOM、许可证检查、漏洞扫描、构建签名、发布 provenance 和回滚包纳入 CI。
- 外部输入、压缩包、CAD 文件、求解器日志和 LLM 响应均按不可信数据处理；限制路径穿越、资源耗尽和命令注入。
- 定义备份保留、恢复时间目标、恢复点目标、数据删除、审计保留和安全事件处理流程。
- 维护支持矩阵：Python、Node、OS、求解器版本、CAD 格式、数据库 schema 和 API 版本。

完成条件：威胁模型、依赖审计、权限测试、灾难恢复演练和发布回滚演练均有记录。

## 版本路线与发布门禁

| 版本目标 | 重点 | 进入条件 |
| --- | --- | --- |
| 0.3 | 案例契约、单位/坐标、API v1、数据库迁移、结构静力稳定化 | P0、P1 全部通过 |
| 0.4 | 受控用户/项目边界、对象存储、指标、备份恢复 | P2 核心门禁通过 |
| 0.5 | CAD 拓扑、区域映射、网格质量与收敛 | P3 代表性案例通过 |
| 0.6 | Abaqus 注册适配器与双后端对比 | P4 双后端证据通过 |
| 0.7 | 一项高级结构能力 | P5 对应能力独立通过 |
| 0.8 | 前端可访问性、审计、协作和运维界面 | P6、P7 核心门禁通过 |
| 1.0 | 稳定 API、支持矩阵、迁移/回滚、签名发布和长期维护 | 所有发布门禁通过 |

任何版本不得以“已调用工具”作为能力完成判据。发布至少需要：

- 代码、配置、API、CLI、Studio、文档和包元数据一致。
- 便携 CI、真实求解、安装后导入、数据库迁移、证据校验和安全检查通过。
- 发布范围内所有公开案例具有真实输入、输出、参考来源、误差阈值和可复核运行记录。
- 失败、取消、超时、中断、重试、权限拒绝和产物损坏都有测试与用户可读诊断。
- 发布资产包含 wheel/sdist、SBOM、许可证清单、验证摘要、SHA-256、签名或 provenance 信息。
- 不存在高严重度安全问题、未解释的数值差异、未验证能力或与代码不一致的公开描述。

## 明确不作为目标的内容

- 用 LLM 直接生成或修改未经 schema、范围和工具门禁验证的求解参数。
- 把任意 CAD 文件转换成可直接求解模型而不确认拓扑、区域、单位和边界。
- 用一次成功运行、截图、语言模型解释或单个工具 smoke 证明物理能力正确。
- 在身份、权限、配额、审计和备份尚未完成前宣称支持多租户或高可用。
- 在缺少公开基准、参考解、收敛数据或实验数据时发布非线性、多物理场或 CFD/FSI。

## 治理原则

能力注册、适配器契约、数据 schema、验证基准、API 版本和发布门禁由代码与测试共同定义。文档只描述当前有效事实、明确边界和可核验条件；候选工具、研究方向和未完成接口必须标记为规划或未知。每次发布保留版本、提交、配置摘要、工具版本、输入输出索引、验证结果和完整性校验，保证问题可以定位、结果可以复核、版本可以回滚。
