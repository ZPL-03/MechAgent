# MechAgent 生产级演进目标

本文定义 MechAgent 从本机可验证原型到生产级 CAE/FEA 多智能体平台的目标、边界、依赖和发布门禁。生产级表示输入、执行、结果、证据、权限、失败恢复和版本兼容均有明确契约与验证；公开能力以发布目录和对应证据为准，物理域、CAD 格式和工具覆盖范围逐项验收。

## 目标定义

MechAgent 的目标产品是一个可部署、可审计、可扩展的 CAE/FEA 仿真平台：工程意图经过结构化建模、能力门禁、几何与网格处理、求解器执行、结果评价和证据归档，输出可复核的工程结论。LLM 负责自然语言理解、候选方案和解释；数值结果只能来自已注册工具及其验证证据。

生产发布必须同时满足以下条件：

1. 输入契约、单位、坐标、区域、材料、载荷、边界、分析步和求解控制均可序列化、校验和版本化。
2. 每个能力声明支持范围、工具绑定、失败行为、参考来源、验收阈值和不适用条件。
3. 每个作业具有幂等标识、完整状态机、资源约束、取消语义、失败归因、产物索引和可验证证据。
4. 求解器、网格器、CAD 内核、后处理器和执行器通过稳定适配器契约接入；插件不会依赖进程内隐式状态。
5. 公开 API、SDK、CLI、Studio 和报告使用同一数据契约；兼容性、迁移和弃用规则可执行。
6. 发布范围内的每个工程能力同时具备真实运行记录和至少一类独立验收证据。
7. 凭据、原始 prompt、内部 Agent 状态、第三方日志和工程文件按访问边界处理；安全失败不会静默降级。

## 当前基线与缺口

当前已验证基线覆盖结构线弹性静力梁、矩形板、参数化开孔薄板和矩形实体，默认工具为 CalculiX、CalculiX INP、Gmsh OCC 和本地执行器。Studio 已具备 SQLite 作业记录、独立 worker、取消、重试、重启查询、幂等提交和运行清单校验。代码已注册 Abaqus/Standard 适配器、结果字段选择器、跨工具差异比较器和 Studio 备份工具；本机 Abaqus 运行与跨工具数值比较分别按工具门禁执行，便携 CI 只执行可移植检查。

当前代码基线还提供 `SimulationCase` schema v1 的兼容封装、`/api/v1` 稳定入口和 SQLite
schema v7 事务迁移。案例契约复用 `ModelParams`，补充单位、坐标、区域、请求来源、字段来源、
多分析步和求解控制；旧模型、旧 `/api` 路径和旧数据库可在明确兼容边界内继续读取。Studio
支持配置主体的 Bearer API key、角色和项目范围，结果写入内容寻址对象存储，备份清单可验证
数据库、作业目录和对象存储。上述能力的验证范围是单个 Studio 数据库；外部身份提供商、分布式调度和高可用尚未完成部署验收。

尚未完成的生产能力：

- 集中式组织目录、外部身份提供商、跨服务集中审计和分布式租户调度。Studio 已提供本地持久主体目录、主体创建/停用/密钥轮换、组织和项目范围、组织字段隔离及审计事件记录；这些能力仍限于单个 Studio 数据库。
- 生产部署的跨主机 RTO/RPO 演练、磁盘资源观测和对象存储权限与保留策略。
- Abaqus 集群许可证容量、跨主机队列高可用，以及跨网格场量逐节点对应的统一比较证据。
- 通用 CAD 直接拓扑网格、跨格式面/边语义确认、装配体连接与接触、网格收敛自动控制和统一网格质量模型。当前受控三维实体支持直接 C3D4 网格和有限区域映射；多实体可生成带 `unconnected_parts` 标记的检查网格，CalculiX 与 Abaqus 求解仍在缺少连接或接触契约时拒绝。
- 非线性、接触、屈曲、模态、动力学、热结构、多物理场、CFD/FSI 和优化的发布能力。
- 集群许可证容量审计、可信构建 provenance、已签名发布、漏洞响应和长期兼容策略。

上述项目属于发布条件，验收依据是实现、运行产物和独立验证证据。

## 总体架构目标

```text
客户端 / SDK / CLI
        ↓ 版本化 API
身份、项目、权限与审计层
        ↓
作业服务 ── 队列 ── 调度器 ── Worker Supervisor
        ↓                         ↓
仿真案例契约                 工具适配器注册表
        ↓              ┌──────────┼──────────┐
能力门禁与评价器       CAD/网格   求解器    后处理
        ↓              └──────────┼──────────┘
证据索引与对象存储 ← 运行产物、日志、报告、场量
```

`mechagent-core` 负责稳定的数据模型、工具抽象、材料/后处理/验证基础能力；`mechagent` 负责 API、SDK、CLI、编排、队列、权限边界和知识层。工具通过注册名、工厂函数、能力声明和版本化适配器契约接入，Abaqus、CalculiX、文件格式和中间表示均由对应扩展实现提供。

## 迭代阶段

### P0：发布基线治理

该阶段聚焦可持续维护的工程基线，物理范围保持在已验证能力内。

- 统一版本、API 路径、配置 schema、能力 ID、错误码、状态枚举和证据 schema。
- 为数据库、运行清单、API 响应和 Pydantic 模型定义版本迁移策略；未知未来版本必须拒绝读取。
- 删除重复文档、过期截图、失效示例和未引用资源；每个专题只保留一个权威入口。
- 固化便携 CI、Windows 真实求解、前端构建、包安装、文档构建、清理和证据校验门禁。
- 生成 SBOM、许可证清单、构建元数据和可复核 SHA-256；发布 tag 与包版本必须一一对应。

完成条件：干净环境可安装、可运行、可验证；文档、OpenAPI、配置、CLI 帮助和代码路由无漂移；没有高严重度未决缺陷。

### P1：稳定仿真案例与契约层

目标是让结构静力成为可长期兼容的参考能力。

- 完善 `SimulationCase`，覆盖 `GeometryModel`、`Region`、`MaterialModel`、`LoadStep`、`BoundaryCondition`、`SolverControl` 和 `ResultField` 的版本化契约。
- 单位和坐标转换集中管理；禁止通过字段名称或自然语言猜测单位。
- 能力注册项声明输入 schema、工具、支持几何、边界、结果字段、评价器、参考来源和失败代码。
- 解析器输出候选值、来源、置信度和缺项；低置信度或越界输入不得进入求解。
- 报告分开表达执行成功、数值提取成功、参考验收通过和工程适用性。

当前实现状态：案例版本、受限单位换算、基线坐标系、区域来源、请求来源、求解控制、
`LoadStepSpec`、`ResultFieldSpec` 和执行前来源置信度门禁已具备。`SimulationCase` 默认要求
六类字段来源及所有载荷/边界区域具有显式 `confidence >= 0.80` 才能进入网格和求解；缺失
置信度的旧兼容案例仍可读取，但必须在执行前补齐来源证据。分析步支持顺序、载荷比例、
增量和结果字段引用校验，结果字段支持位置、分量/不变量、单位和必需性声明。CalculiX 与
Abaqus/Standard 的 `run_case()` 支持线性静力多步，结果字段选择器统一生成分量/不变量值；
显式单位与后端场不一致的必需字段会失败，选定字段和单元映射字段保留来源与推导信息；
完整场量的后端覆盖和非静力分析仍未进入发布能力。

完成条件：TC-01 至 TC-05、28 个自然语言案例和边界案例全部通过契约校验；输入、报告和证据可在兼容版本间迁移。

### P2：可部署的执行与平台层

目标是把单机运行层提升为受控服务。

- API 使用明确版本前缀、OpenAPI schema、错误码、分页、限流和超时；旧客户端拥有弃用周期。
- 增加身份认证、项目隔离、角色权限、作业拥有者、审计事件和工程文件访问控制。
- 作业数据库支持正式迁移、备份、恢复、WAL 处理、归档策略和一致性检查；运行产物进入可配置对象存储。
- Worker Supervisor 管理资源配额、CPU/内存/磁盘限制、容器或受控进程、优雅停止、孤儿回收和重试策略。
- 指标覆盖队列长度、等待时间、执行时间、失败原因、资源使用、产物大小和证据校验；日志结构化并脱敏。
- 重试必须区分可重试基础设施错误、用户输入错误、工具错误和数值未收敛，不自动重跑工程任务。

保留清理、冷备份清单、恢复
入口、RTO/RPO 演练脚本和 `/api/v1/metrics` 脱敏指标接口已实现并有自动化测试。指标包含本机工作目录用量、配额和超额状态；主体目录通过
`/api/v1/identities` 提供组织内主体创建、停用、密钥轮换和范围更新；API key 只保存 SHA-256

### P3：几何、区域与网格闭环

目标是让 CAD 输入保留工程语义，并完成区域、网格和结果映射验证。

- 统一 STEP、IGES、BREP 等格式的单位、坐标系、拓扑实体 ID、面/边/体区域和修复诊断。
- 区域映射必须可见、可编辑、可验证；无法确认的载荷面或约束面进入人工确认状态。
- Gmsh 与其他网格器输出统一节点、单元、区域、质量指标和坐标约定；网格失败保留可诊断中间产物。
- 支持全局和局部尺寸场、质量阈值、网格独立性和收敛报告；单次网格成功状态与收敛状态分别记录。

当前实现状态：Gmsh OCC 已记录源文件 SHA-256、当前摘要内可复现的拓扑摘要、实体包围盒、按三维实体划分的零件摘要和六向区域候选；导入结果生成版本化 `CADArtifact`、`GeometryValidation` 和 `RegionBinding`，确定性校验包围盒、实体水密性、拓扑父子关系、零件归属、源完整性和区域引用，并把 `execution_ready` 传入案例元数据和直接网格门禁。零件摘要保留实体 ID、体积、包围盒以及边界面/边 ID，候选保留所属零件 ID，供检查和人工区域确认，
候选含拓扑 ID、置信度和歧义状态。CAD 候选摘要随 `ModelParams.metadata.cad_geometry` 进入
案例契约；`root`、`tip`、`top_surface`、`bottom_surface` 和 `all_edges` 只有在唯一候选、
拓扑 ID 存在于同一 `topology_entities`、维度匹配且置信度达到 0.80 时才生成
`RegionSpec(kind="topology")`，同时保留 `part_ids`；其他状态保留 `unknown` 并阻断执行。案例投影把完整区域契约写入
`metadata.case_regions`，`gmsh-cad-inp` 对已声明区域只按该契约建立节点集合，未声明区域才使用兼容候选补充，并拒绝未知、重复或维度不匹配的拓扑 ID。成功网格结果必须指向实际存在的网格文件，并在结果元数据中记录该文件的
`mesh_sha256`；MeshAgent 和 SolverAgent 均校验文件摘要，文件缺失或摘要不一致会阻断求解。成功结果同时生成版本化 `MeshResult.provenance`，保存案例、几何、网格器、尺寸、单元类型、质量指标、质量门禁、区域名称和可用 CAD 摘要；该对象不包含网格收敛或跨网格器等价性结论。内置网格器统一声明质量指标：梁结构化网格使用 `min_jacobian`，参数化板和 CAD 直接网格使用 `min_sicn`，结构化实体使用 `min_edge_ratio` 和 `max_aspect_ratio`。网格门禁把所有 `min_*` 指标与 `min_quality` 比较，并在 `metadata.quality_gate` 保存阈值、指标名称和状态；上界指标保留在 `quality` 中供报告使用。该映射已在确定性实体和带贯穿圆孔实体上通过 `gmsh-cad-inp` 的直接
STEP 网格、面到节点集合映射、C3D4 质量检查和 CalculiX 真实求解证据；多实体可完成零件归属、区域节点集合和 C3D4 检查网格，网格元数据明确标记 `connection_semantics=unconnected_parts`，求解器在缺少接触、连接或装配约束时拒绝；复杂薄壁件和通用 CAD 修复仍未完成。`mechagent_output/mesh-convergence-tc01/manifest.json`
记录 TC-01 在 seed size 40、20、10、5 mm 的四次 CalculiX 真实运行；终点节点/单元数为
201/200，终点相邻网格相对变化为 2.014e-5，解析参考相对误差为 0.1031%，收敛清单状态为
`passed`。该证据范围为参数化 B31 梁。CAD 单实体网格独立性脚本和实体块证据已建立；贯穿孔案例当前只有无参考值的 `unverified` 稳定性记录，多区域装配、其他单元族和跨网格器质量等价性仍需独立验收。

完成条件：代表性梁、板、实体、带孔零件和含多个区域的 STEP 案例通过拓扑、区域、网格质量、收敛和结果映射验收。CAD 实体网格收敛必须使用固定源文件 SHA-256、拓扑摘要和区域契约摘要，逐尺寸保存完整结果场；只有同时具备参考值、终点相邻网格变化、质量门禁和结果字段证据时才进入 `passed`。

### P4：跨工具结构静力验证

目标是形成可比较的结构静力适配器闭环，当前验证工具包括 CalculiX 和 Abaqus/Standard。

- 实现 Abaqus 注册适配器，明确 Standard/Explicit、输入模板、材料、单元、边界、作业状态、ODB 字段和失败映射。
- 许可证检查、命令启动、子进程树、超时、锁文件和 ODB 完整性均由适配器负责。
- 同一 `SimulationCase` 在选定工具中生成可比较的模型摘要、位移、应力、反力和能量字段。
- 差异报告记录单元、网格、边界、求解控制和后处理差异；比较条件包括一致的模型摘要和明确的误差阈值。

当前实现状态：Abaqus/Standard 已注册，支持当前结构静力族的输入生成、作业启动、ODB 多帧
场量提取和多分析步输出；CalculiX 已提取位移、应力、反力和能量场；共享结果选择器、原始场
保留、统一单元质心映射和 `scripts/run_backend_comparison.py` 已提供跨工具差异报告。TC-01、
TC-03、TC-04 在本机 Abaqus/Standard 与 CalculiX 上完成真实运行。请求位移字段使用节点坐标或
梁中心线对应；统一单元质心字段包含应力 `stress_sxx`、应变 `strain_exx`、体积 `volume`，实体
案例还包含 `strain_energy_density`；统一语义字段比较应力全场绝对最大分量、由各向同性线弹性
本构重建的应变能密度摘要以及最大跨度方向支撑区域反力合力；反力平衡校核可计算的外载合力与支撑边界反力。统一单元质心字段相对误差阈值为
10%，统一语义摘要相对误差阈值为 3%，绝对阈值均为 0.005。证据位于
`mechagent_output/backend-comparison-current/manifest.json`，三个案例的请求字段、
统一单元质心字段、统一语义字段和反力平衡均为 `passed`。结果根据节点坐标和单元连接生成 `mesh_digest`，
仅在两侧指纹一致时允许 `element` 或 `integration_point` 场按键比较；真实跨工具案例的网格不同，
原始场仍存在节点/积分点、梁截面展开和离散标签差异，`raw_fields` 对这些字段保留 `unverified` 或 `failed`；逐积分点应力、逐节点反力和原始能量场的跨工具等价性仍未验收。Abaqus 双步 TC-01
的完整场提取清单已通过，包含两个分析步和每步两个输出帧；`scripts/run_calculix_multistep.py`
的 FRD 清单也已通过，包含两个分析步和每步一个结果帧，逐步覆盖位移、应力、应变、体积、应变能密度、反力和能量。CalculiX
的应力、应变和反力保持节点位置，体积、应变能密度和能量保持单元位置。许可证策略支持进程内信号量和可选的
共享 SQLite 租约队列，队列具有容量漂移检查、心跳续租、过期回收和超时失败；本机 FlexNet 只读
审计清单已通过，集群许可证服务容量和跨主机高可用仍需部署验收。应力、反力、能量的原始场映射、更广泛单元族、网格和
工程案例仍需独立的跨工具验收。

完成条件：至少三类结构静力模型完成同一案例的跨工具比较；每个选定工具均有独立安装、失败路径、许可证不可用和结果字段测试。

### P5：高级结构与多物理能力

各能力独立发布，版本按能力分别验收：

| 能力 | 必要契约 | 发布证据 |
| --- | --- | --- |
| 几何/材料非线性 | 增量步、状态变量、收敛准则、路径输出 | 公开基准、步长/容差收敛、失败诊断 |
| 接触 | 接触对、法向/切向、摩擦、初始间隙 | 接触基准、穿透检查、能量与收敛 |
| 屈曲/模态 | 特征值、预应力、模态归一化、边界 | 解析或公开基准、特征值误差、模态质量 |
| 瞬态/动力学 | 时间步、初始条件、阻尼、时程与能量 | 时间步收敛、能量守恒、公开时程 |
| 热/热结构 | 温度场、材料温度依赖、场映射、单位 | 守恒、场映射误差、网格/时间收敛 |
| 优化/设计探索 | 变量、约束、目标、采样、独立校核 | 基准优化、代理误差、复算和停止原因 |

每项能力达到“研究、可执行、可验证、发布”四级门槛后才进入公开能力目录。

### P6：前端与工程协作

- Studio 提供请求、预检、作业、模型、网格、场量、报告、证据和审计的可追踪链路。
- 3D 视口显示节点、单元、场量来源、单位、坐标和变形倍率；缺少网格或场量时显示不可用状态。
- 支持中英文、明暗主题、键盘操作、可见焦点、屏幕阅读器语义、窄屏布局和 reduced-motion。
- 运行中的取消、断线、权限拒绝、队列满、结果缺失、证据失效和未验证状态必须在界面中可理解地呈现。
- 组件、颜色、间距、字体、图标和状态反馈全部来自设计令牌；设计系统与代码组件保持可追踪映射。

完成条件：WCAG 2.2 AA 核心检查通过；真实作业、失败作业、断线恢复、权限边界和大结果集均有浏览器验收。

### P7：安全、供应链与运维

- 密钥只来自受控运行时，禁止进入数据库、manifest、日志、报告、前端响应和构建产物。
- 依赖锁定、SBOM、许可证检查、漏洞扫描、构建签名、发布 provenance 和回滚包纳入 CI。
- 外部输入、压缩包、CAD 文件、求解器日志和 LLM 响应均按不可信数据处理；限制路径穿越、资源耗尽和命令注入。
- 定义备份保留、恢复时间目标、恢复点目标、数据删除、审计保留和安全事件处理流程。
- 维护支持矩阵：Python、Node、OS、求解器版本、CAD 格式、数据库 schema 和 API 版本。

当前实现状态：`docs/MechAgent-threat-model.md` 根据本机或受控内网、本地 API key 和工程数据保护假设，记录 API、身份权限、队列 worker、外部工具、对象存储、备份、LLM 和 CI 发布边界；外部身份、跨主机隔离、S3 部署策略和可信签名仍需部署验收。

完成条件：威胁模型、依赖审计、权限测试、灾难恢复演练和发布回滚演练均有记录。

版本完成判据包括：

- 代码、配置、API、CLI、Studio、文档和包元数据一致。
- 便携 CI、真实求解、安装后导入、数据库迁移、证据校验和安全检查通过。
- 发布范围内所有公开案例具有真实输入、输出、参考来源、误差阈值和可复核运行记录。
- 失败、取消、超时、中断、重试、权限拒绝和产物损坏都有测试与用户可读诊断。

- `scripts/sign_release.py` 支持受控密钥和 GitHub OIDC keyless 模式；签名密钥保留在受控发布环境，未签名资产保持未发布状态。`.github/workflows/release.yml` 仅在显式版本 tag 上执行可信 CI 签名和发布。
- 高严重度安全问题、未解释的数值差异、未验证能力和与代码不一致的公开描述均已闭合。

## 范围外能力

- 用 LLM 直接生成或修改未经 schema、范围和工具门禁验证的求解参数。
- 把任意 CAD 文件转换成可直接求解模型而不确认拓扑、区域、单位和边界。
- 用一次成功运行、截图、语言模型解释或单个工具 smoke 证明物理能力正确。
- 多租户或高可用的发布条件包括身份、权限、配额、审计和备份的完整验收。
- 在缺少公开基准、参考解、收敛数据或实验数据时发布非线性、多物理场或 CFD/FSI。

## 治理原则

能力注册、适配器契约、数据 schema、验证基准、API 版本和发布门禁由代码与测试共同定义。文档只描述当前有效事实、明确边界和可核验条件；候选工具、研究方向和未完成接口必须标记为规划或未知。每次发布保留版本、提交、配置摘要、工具版本、输入输出索引、验证结果和完整性校验，保证问题可以定位、结果可以复核、版本可以回滚。
