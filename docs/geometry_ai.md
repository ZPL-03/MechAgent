# 几何建模与网格边界

本文定义 MechAgent 的几何职责、自动化建模边界、CAD 导入路径、网格可信条件和相关开源项目的使用位置。它与[能力与自然语言解析](capabilities.md)、[求解器、网格与后处理](solver_mesh.md)和[长周期开发计划书](development_plan.md)配合使用；求解器数值验证见对应专题。

## 工程结论

自然语言可以帮助选择几何模板、补全参数、生成参数化 CAD 脚本和解释检查结果。复杂工程 CAD 的验收依据包括结构化意图、受控几何生成或导入、确定性几何检查、区域绑定、网格质量检查和求解验证；任一步失败都保留诊断并停止后续求解。

`text-to-cad` 对本项目有帮助，适合接入为隔离的几何生成后端或脚本生成参考：它能使用 build123d/OpenCASCADE 生成可编辑 Python 和 STEP 等实体文件。MechAgent 仍需独立执行 CAD 内核、区域语义、网格质量和求解验证；其上游 FEA 路径与 MechAgent 当前的 C3D8R/C3D4、结果字段和案例契约存在接口差异。

当前仓库没有把 `text-to-cad` 作为运行时依赖，也没有声称已经提供其适配器。接入前应先建立隔离 Python 3.13 运行时和最小 CLI 边界，再把生成脚本、STEP 文件、版本和哈希交给 MechAgent 的几何门禁。

## 当前两条几何路径

### 参数化仿真几何

自然语言或结构化输入经过 `static_parser.py` 生成 `ModelParams`。当前发布范围包含：

| 几何族 | 参数化网格 | 当前求解范围 |
| --- | --- | --- |
| 悬臂梁 | 结构化线网格，B31 | 端部集中力或全跨均布线载荷，一端固支 |
| 矩形薄板 | Gmsh 壳网格，S4 | 四边简支，均布压力 |
| 圆孔、多孔、长圆槽孔薄板 | Gmsh OCC 壳网格，S3/S4 | 外边界简支，孔边自由，均布压力 |
| 矩形实体块 | 结构化六面体，C3D8R | 一端固定，端面轴向压力或合力 |

这条路径的几何是有限集合中的参数模型，范围覆盖既定参数；STEP 特征历史、自由曲面、装配约束和用户 CAD 原始拓扑由真实 CAD 路径处理。

### 真实 CAD 拓扑路径

`GmshCADKernel` 通过 Gmsh OpenCASCADE 导入 STEP、IGES 和 BREP，计算源文件 SHA-256、包围盒、体积、表面积、实体/面/边计数、封闭性、按三维实体划分的零件摘要、当前摘要内可复现的拓扑实体和六个包围盒方向的区域候选。零件摘要包含三维实体 ID、包围盒、体积、边界面 ID 和边 ID；区域候选同时记录候选面所属的零件 ID。`GeometryAgent` 将摘要转换为 `GeometryCandidate`，再由自然语言补全材料、载荷和边界。案例提升会核对区域拓扑 ID 是否存在于同一摘要，面区域使用二维实体，`all_edges` 使用一维实体，并把零件归属写入 `RegionSpec.part_ids`；不满足条件的区域保持 `unknown`。

`gmsh-cad-inp` 从受控 CAD 源重新导入单个三维实体，生成一阶 C3D4 四面体网格，并把案例投影中的 `metadata.case_regions` 与 CAD 候选区域映射为节点集合。它检查源文件哈希、拓扑摘要、区域拓扑 ID、面/边维度、必需区域和 Gmsh `minSICN` 质量；多实体装配、缺少受控源、拓扑漂移、区域未映射或质量低于阈值时失败，不回退为包围盒网格。多实体文件仍可生成零件级几何候选供人工确认，但不进入该求解路径。

当前真实证据覆盖确定性实体和带贯穿圆孔实体；以下能力尚未发布：

- 任意装配体、接触关系、薄壁壳、开放曲面或非流形几何的直接求解；
- 几何意图、设计历史和工程特征的可靠恢复；
- 自动删除小孔、短边、圆角、倒角或其他特征；
- 任意区域名称到 CAD 面的长期稳定映射；当前 ID 只在相同摘要和导入配置下有效；
- 任意 CAD 单元族、二阶四面体、六面体主导网格或跨网格后处理等价性。

包围盒尺寸只能生成候选几何类型；特征识别需要拓扑和几何检查。梁、板和实体的推断在薄度和细长比改变时可能与工程意图不一致，必须由用户或后续约束确认。

## 复杂几何的可实现性

“复杂几何”需要按几何来源、拓扑结构和分析语义分别判断：

| 类型 | 自动化组件可以承担的工作 | 当前可信边界 |
| --- | --- | --- |
| 规则零件、梁、板和孔槽参数模型 | 从自然语言提取参数、选择模板、生成候选脚本和解释检查结果 | 当前参数化模型可以进入既有网格与结构静力验证；仍受尺寸、材料、边界和载荷契约约束 |
| 单一封闭 BRep 实体、区域清晰的 STEP | 生成导入候选、补全分析意图、绑定已确认的面/边并调用直接网格 | 当前 `gmsh-cad-inp` 的证据范围是受控三维实体和有限区域映射；其他 CAD 需要独立证据 |
| 装配体、薄壁件、自由曲面、非流形或接触结构 | 生成候选分解、提出区域和网格策略、整理人工复核清单 | 装配约束、接触语义、薄壁壳建模和稳定载荷区域需要人工确认或独立研究流程 |

自然语言生成复杂 CAD 的可行性取决于几何约束、特征表达和验证覆盖。可靠路线是让模型生成受约束的参数/特征程序，把 OpenCASCADE 等内核当作确定性执行器，再用几何回读、区域绑定、网格质量、反力平衡和网格收敛逐级筛选候选。拓扑或物理语义无法确认时，系统保留候选并进入人工确认状态。

## CAD 清理的当前含义

当前 `healing=True` 且导入结果为单个三维实体时，Gmsh OCC 导入摘要路径会调用 `healShapes()`；多实体文件跳过该操作，以保留零件拓扑，摘要通过 `healing_applied=false` 明确记录。直接 CAD 网格适配器仍只接受单个实体。该操作属于内核级形体修复尝试，完整 CAD 清理还需要特征处理、尺寸容差和区域回归证据。摘要中的 `watertight` 由面边使用次数检查得到，作为当前导入形体的门禁信号；制造性、几何精度和物理边界需要单独验证。

`healing` 可能影响导入后的拓扑摘要，因此生成候选和直接网格必须使用相同的配置；网格适配器发现源文件哈希或拓扑摘要不一致时会拒绝执行。

`CADConfig.min_feature_size` 在 core schema 中存在，但当前 Gmsh 适配器没有使用它执行去特征，因此文档和产品界面不得把它描述成已经生效的自动去特征参数。后续实现去特征时，需要把原始文件、修复后文件、操作列表、尺寸容差、体积/面积变化和区域映射变化写入可审计的修复报告；没有这些证据时只能报告“已尝试修复”或“未执行去特征”。

## 几何候选生成与验证闭环

复杂几何应采用“意图约束—候选生成—确定性检查—接受版本”的闭环：

1. 把自然语言转换为结构化意图：单位、坐标系、零件和装配关系、尺寸、特征、约束、制造限制、材料、载荷区域、边界区域和分析类型。
2. 从受控 primitive、参数化零件模板或已有 CAD 特征检索候选，不让模型直接决定未定义的拓扑细节。
3. 在隔离运行时调用 build123d、CadQuery、FreeCAD 或其他明确登记的 CAD 后端，生成脚本和 CAD 文件；脚本、依赖版本和输入参数必须留存。
4. 对候选执行确定性检查：实体数量、封闭性、自由边、自相交、体积、面积、包围盒、关键尺寸、孔径、圆角、最小壁厚、干涉、间隙、连通性和材料/制造约束。
5. 导出 STEP/BREP 后重新导入回读，比较体积、面积、包围盒、关键特征和拓扑摘要；回读失败或漂移超过容差时拒绝候选。
6. 把具体失败诊断反馈给生成器进行有限次数的重试；每次重试都保存输入、诊断和输出哈希。
7. 只有满足几何门禁的候选才进入 `accepted` 状态，并绑定几何版本、源文件哈希、内核和修复报告。
8. 进入网格阶段后，检查 CAD 区域映射、节点/单元集合、质量分布、局部尺寸场、反力平衡和网格收敛；这些检查与求解状态分别记录。
9. 对多解、歧义区域、复杂曲面和高风险特征保留人工确认门禁。

这条闭环允许 AI 参与建模，工程正确性由可复核产物和确定性检查判断。视觉相似度、脚本执行状态和体积接近度只能作为候选信息，接受复杂 CAD 还需完成几何、区域、网格和求解门禁。

## 建议的数据契约

下列对象是后续扩展方向，当前仓库已有部分字段，但尚未形成完整的独立版本化契约：

| 对象 | 必须记录的事实 | 进入下一阶段的条件 |
| --- | --- | --- |
| `CADArtifact` | 原始/处理后路径、格式、单位、坐标系、源 SHA-256、几何版本、CAD 内核和版本、生成脚本或参数来源、修复报告 | 文件可读、来源可追踪、版本唯一 |
| `GeometryValidation` | solid/face/edge 数、封闭性、自由边、自相交、体积/面积/包围盒、关键特征测量、错误和警告 | 所有必需检查通过，警告有处置结论 |
| `RegionBinding` | 语义名、拓扑 ID、映射方法、置信度、几何版本、歧义状态、人工确认 | 每个载荷/边界区域唯一映射且版本匹配 |
| `MeshProvenance` | 网格器和版本、CAD 摘要、单元类型、尺寸场、质量指标、区域集合、收敛状态 | 网格文件存在、质量门禁和区域门禁通过 |

这些对象属于规划项。现有 `CADGeometrySummary`、`GeometryCandidate`、`RegionCandidate` 和 `MeshResult.metadata` 覆盖其中的部分字段，完整版本化契约仍待建立。

### 相关开源项目的定位

- `diagram-design` 是 Agent Skill 和 HTML/SVG 视觉规范，适合用于架构图、工作流图、验证闭环图和 Studio 帮助内容。图形属于解释性产物，数据来源仍来自代码和证据清单；CAD 和网格生成由其他工具负责。
- `mattpocock/skills` 是面向工程开发的可组合技能集合，强调需求澄清、共享术语、规格、TDD、故障诊断和架构改进。其内容适合转化为 MechAgent 的开发流程和文档规则，运行时行为仍由本项目代码和测试定义。
- `morluto/rea` 是本地 MCP 逆向工程和证据工作流，强调工具提供者、快照、证据和结果限制。对 MechAgent 的参考价值是为 CAD/网格/求解工具保留来源、版本、原始诊断和可复现快照；其逆向工程能力与 CAE 几何能力属于不同问题域。
- `text-to-cad` 是四个项目中直接涉及实体 CAD 生成的项目。接入路径为“生成候选—回读检查—区域绑定—网格门禁”，自然语言到 STEP 的单次运行只产生候选文件。

## 网格可信条件

网格阶段至少需要同时回答四个问题：

1. 网格是否来自正确的几何版本和单位？
2. 载荷、边界和材料区域是否映射到正确的面、边、节点或单元集合？
3. 单元质量、局部特征分辨率和自由度约束是否满足求解器契约？
4. 结果是否经过反力平衡、参考解和网格收敛检查？

当前 C3D8R 参数化实体与 C3D4 直接 CAD 实体属于不同路径，各自的网格数量、质量和结果字段分别验收。跨工具比较还必须保持同一 `SimulationCase`、单位、坐标系、边界、载荷、结果位置和误差阈值。

## 路线与成熟度门禁

| 阶段 | 目标 | 进入条件 |
| --- | --- | --- |
| P0 事实收敛 | 统一术语、能力矩阵、脚本职责和文档入口 | 代码、测试和文档不互相夸大 |
| P1 几何产物 | 版本化 CAD artifact、几何验证和修复报告 | 文件哈希、单位、坐标系和回读结果齐全 |
| P2 参数化建模 | 隔离生成器、模板检索、有限重试和接受版本 | 候选几何检查与 benchmark 通过 |
| P3 CAD 修复与去特征 | 可解释的 healing、defeaturing 和特征识别 | 体积/区域/拓扑变化可审计，失败显式暴露 |
| P4 直接 CAD 网格 | 多实体、局部尺寸场、区域绑定和质量门禁 | 代表性实体、孔、薄壁和曲面案例通过 |
| P5 网格与结果可信 | 网格收敛、反力平衡、跨工具语义比较 | 每个公开能力具有参考误差和运行证据 |
| P6 复杂结构 | 薄壁、装配、接触、非线性或多物理 | 每个物理域独立建立契约和基准 |
| P7 研究型生成模型 | Text2CAD、BRep/mesh 生成和数据集实验 | 研究报告与生产能力严格隔离 |

“研究”“可执行”“可验证”“发布”是四个不同状态。生成文件、启动网格器和完成求解分别记录；进入“可验证”或“发布”还需要对应的检查和证据。
