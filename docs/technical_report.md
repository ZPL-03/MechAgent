# MechAgent 技术报告

## 产品范围

MechAgent 是开源 CAE/FEA 多智能体编排框架。它把自然语言工程请求转换为结构化仿真案例，经过能力门禁、网格、求解、结果提取、工程评价和报告输出，保存可复核的运行证据。LLM 只负责意图识别、结构化候选和解释；数值结果来自已注册的网格器、求解器和后处理器。

发布基线聚焦结构线弹性静力，模型族包括悬臂梁、四边简支矩形薄板、圆孔/多孔/长圆槽孔薄板和矩形实体块。内置工具链为 Gmsh、CalculiX、Abaqus/Standard 适配器和本地作业执行器。Abaqus 适配器已注册并实现输入生成、作业启动和 ODB 结果场提取；TC-01、TC-03、TC-04 已完成本机适配器运行。位移字段使用坐标对应和梁中心线重建；统一单元质心字段提供 `stress_sxx`、`strain_exx`、`volume`，实体案例还提供 `strain_energy_density`；统一语义字段提供应力最大分量、应变能密度摘要和支撑区域反力合力的显式比较。权威证据位于 `mechagent_output/backend-comparison-current/manifest.json`，三个案例的请求字段、统一单元质心字段和统一语义摘要均为 `passed`。原始节点/积分点场、梁截面展开场和逐节点反力尚未建立一一映射；统一字段和摘要比较的适用范围为对应的聚合字段和摘要。许可证管理与更广泛工程验收按发布门禁单独记录。

## 分层架构

`mechagent-core` 提供 Pydantic 数据模型、材料目录、CAD 内核、网格器、求解器、后处理器、执行器、验证基准和工具工厂。`mechagent` 提供 SDK、CLI、Studio 服务、Planner/Designer/Mesh/Solver/PostProc/Analyst/Reporter 编排链路、LLM 接入和知识层。React/TypeScript Studio 位于 `apps/mechagent-studio`，构建产物随 `mechagent` 包发布。

求解器、网格器、CAD 内核、后处理器和执行器通过注册名、工厂函数、适配器契约和能力声明接入。跨层结构化数据使用 Pydantic v2 模型；`SimulationCase` schema v1 作为 API、编排、工具和证据边界的版本化封装，兼容转换保留旧 `ModelParams` 调用方。

## 执行契约

`SimulationCase` 明确声明单位、右手坐标系、载荷/边界区域、请求来源、字段来源和求解控制。`to_model_params()` 只执行案例声明的单位换算，不根据字段名称或自然语言推断单位。

案例同时包含有序 `load_steps` 和 `result_fields`。分析步记录分析类型、几何非线性、载荷工况继承、
载荷比例、增量、输出间隔和结果字段引用；结果字段记录物理量、位置、分量或不变量、单位及是否
必需。旧案例读取时补齐一个默认分析步和主位移请求。旧 `ModelParams` 入口仍只接受单步；
CalculiX 与 Abaqus/Standard 的 `run_case()` 路径支持线性静力多步和逐步结果场。Abaqus ODB
提取保留节点坐标、节点位移/反力、积分点应力/应变/应变能密度、单元体积、全局能量和
历史能量；积分点键包含元素标签、积分点和截面点，避免场值覆盖。

进入网格和求解前，`SimulationCase.execution_readiness()` 检查几何、材料、载荷、边界、网格、分析六类来源以及全部载荷/边界区域来源的置信度。默认门槛为 `0.80`。缺失或低于门槛的旧兼容案例可以读取和迁移，但 `ensure_execution_ready()` 会阻断执行并生成 `execution_not_ready` 错误。参数范围、能力执行契约和工具注册检查在同一执行链路中生效。

执行状态与工程验收分开表达：`success` 表示进程和结果提取完成，`verification_status` 表示参考验收状态，`passed` 表示在存在参考值和阈值时通过工程校核。缺少参考值的结果标记为 `unverified`，不等同于工程验收通过。

## 接口与运行层

Studio 稳定 HTTP 入口为 `/api/v1`，旧 `/api` 路径用于兼容已有本地集成并带弃用响应头。Studio 使用 SQLite 作业记录、独立 worker、幂等提交、取消、重启查询、并发限制、按主体与客户端地址的进程内 API 限流、项目级活动作业配额、本机工作目录磁盘配额、结果大小上限、组织和项目范围过滤、Bearer API key 角色检查、可配置的本地或 S3 内容寻址结果对象、运行清单校验和受权限保护的脱敏指标接口；指标由持久化作业计算状态计数、队列等待、执行时长、失败代码、结果字节数、证据完整性、本机工作目录用量与配额以及 worker 和可见子进程的 CPU 时间与峰值常驻内存。超额提交返回 HTTP 507，超额结果以 `storage_quota_exceeded` 失败；本机配额统计本地目录，S3 容量单独管理。持久主体目录通过 `/api/v1/identities` 支持同组织主体管理、停用和密钥轮换，数据库只保存 key 摘要；当前调度范围为本机队列，外部身份提供商、集中审计、集群调度和高可用属于部署扩展。

`inspect` 预检只执行 Planner，返回缺项、置信度和执行阻断原因；只有 `complete=true` 且 `execution_ready=true` 才报告请求可进入执行链路。

SDK、CLI 和 Studio 使用同一编排模型及公开摘要。公开响应保留任务、状态、错误、结果、产物和审计元数据，不输出原始 prompt、LLM response 或密钥。运行目录中的输入、网格、求解输出、报告和 manifest 按文件校验和保存，文件完整性与工程参考验收分别判断。

## 验证证据

维护基线包括 5 个 CalculiX 标准验证算例、28 个自然语言案例和 15 项 LLM smoke 检查。Python 测试、便携测试和真实 CalculiX 回归由质量门禁执行；Ruff、mypy、MkDocs strict、两个包的 wheel/sdist 构建、隔离 wheel 安装烟测和 `pip check` 同样以当前命令输出为准。前端测试、TypeScript/Vite 构建、生产依赖审计、SBOM、发布清单、构建 provenance 和 Python 运行时依赖审计由质量门禁统一检查。

验证命令、算例误差、环境边界、依赖审计和清理策略见[验证与质量门禁](validation.md)。标准算例和自然语言案例的具体范围见[能力与自然语言解析](capabilities.md)及[求解器、网格与后处理](solver_mesh.md)。

## 发布条件

公开发布前仍需完成远端对象存储部署验收、跨主机磁盘配额与外部 telemetry 汇聚、许可证人工审计、签名资产在可信 CI 中的验证、CAD 装配体与多区域覆盖，以及更广泛的跨网格工程验收。仓库安全风险和防护边界见[安全风险与防护边界](MechAgent-threat-model.md)，部署级缺口按实际环境单独验收。参数化 B31 梁的网格收敛闭环已有真实证据，位于 `mechagent_output/mesh-convergence-tc01/manifest.json`：四个 seed size 为 40、20、10、5 mm，终点相邻网格相对变化为 2.014e-5，解析参考相对误差为 0.1031%，状态为 `passed`。该证据范围为参数化 B31 梁；CAD 实体、多区域和其他单元族需要单独的网格独立性验收。实际 Studio 数据库的本地备份恢复演练已通过，证据位于 `mechagent_output/studio-recovery-evidence/manifest.json`：源库与恢复库完整性为 `ok`，1 个终态作业的作业 ID 全部保留，RTO 约 0.089 秒，阈值为 60 秒。当前已有持久主体目录、项目配额、备份恢复工具、S3 客户端、Abaqus 许可证探针、坐标对应和单元质心比较器、worker CPU/内存指标和 keyless 签名工作流；外部身份提供商、高可用调度、跨主机恢复和已签名公开发布需要独立部署证据。CAD 直接网格已在确定性实体和带贯穿圆孔实体上通过 C3D4、区域节点集合、质量、CalculiX 和结果场验证；装配体、复杂薄壁件和自动网格质量统一模型仍未覆盖。TC-01、TC-03、TC-04 的请求字段、统一单元质心字段和统一语义字段已有真实比较清单；原始积分点/节点场的一一映射仍未验证，单元聚合和摘要比较的适用范围限于对应字段。非线性、接触、屈曲、动力学、多物理场和优化能力必须分别完成输入契约、真实工具产物、独立验证证据和失败路径后才能进入公开能力目录。

发布门禁要求代码、配置、API、CLI、Studio、包元数据和文档一致；安装后导入、数据库迁移、真实求解、证据校验、安全检查和回滚依据齐全；发布范围内不存在未解释的数值差异、未验证能力或高严重度安全问题。长周期依赖关系和阶段完成条件以[长周期开发计划书](development_plan.md)为准。
